## Learned User Preferences

- All code changes must be backwards compatible and non-destructive to existing user data and setup; migrations should preserve or recover data, not silently wipe it.
- Tests must never read or write live user data under `~/PrintQueData`; the app and pytest should be safe to run at the same time.
- When implementing an attached plan: do not edit the plan file; use the existing todos (do not recreate them); mark each in progress and finish all before stopping.
- Prefer concise, direct answers when asked what changed or how something works.
- When fixing lint/format issues, run the linter and fix what it reports directly instead of many exploratory diagnostic commands.
- Frontend changes must pass Biome before the task is done — husky pre-commit runs `biome check --write` on staged `app/**/*.{js,ts,tsx,json}` and **errors block commits**. Run `cd app && npm run lint` after edits; fix with `npm run lint:fix` or `npx biome check --write --unsafe .` when Biome suggests unsafe fixes (e.g. `useExhaustiveDependencies`).
- Queue quantity, delete, and inline ejection/cooldown edits should use optimistic client cache updates (patch on mutate, revert on error); quantity/delete use debounced API sync so rapid clicks feel instant without waiting for the next poll.
- Do not commit local Cursor hook state (`.cursor/hooks/state/`, e.g. continual-learning index/json); commit shared `.cursor/rules/` and hook scripts only.
- Do not manually bump version in `api/__version__.py` or `pyproject.toml`; mark breaking changes with `feat!:` / `BREAKING CHANGE:` and let CI semantic-release update version on merge to `main`.
- After a failed pre-commit, check `git stash list` for `lint-staged automatic backup` — lint-staged stashes staged changes on hook failure and can make work appear lost until restored with `git stash pop`.

## Learned Workspace Facts

- Monorepo layout: Python Flask API in `api/`, React/Vite UI in `app/`. Local dev from repo root: `pnpm run dev` (UI) and `pnpm run api` (Flask) via root `package.json` scripts. On Windows, stopping the terminal may leave prior `python app.py` orphans running — kill them before another `pnpm run api` to avoid duplicate background threads and stale `printers_rwlock` logs. No Jinja templates under `api/` — SSR page routes were removed; `app.py` `serve_frontend()` is the canonical React host (`endpoint='index'` preserves legacy `url_for('index')` redirects from remaining form POST routes). Frontend Biome config in `app/biome.json`; repo-root `.vscode/settings.json` with Biome format-on-save and `biome.configurationPath: app/biome.json`. Do not gitignore all `*.json` — exclude only root runtime state filenames. Nav routes: dashboard (`/`), full **Library** (`/library`) and **Orders** print queue (`/orders`) with client-side search and pagination (default 30, options 30/50/100; URL `q`, `page`, `pageSize`); dashboard keeps stats/printers plus 5-item newest-first previews linking to those pages. Top nav includes GitHub + Discord icon links from `app/src/lib/community-links.ts` (no frontend `/license` page — support card lives on System). Library/Orders/Printers tables use resizable columns (`resizable-table.tsx`, fit-to-container default) and truncated long names with hover full text (`truncated-text.tsx`). Frontend live data: Socket.IO is primary when connected (`app/src/lib/socket.ts` applies `status_update` via `setQueryData` for printers/queue — do not invalidate `library` on every poll); `useAdaptiveRefetchInterval`/`useApiConnection` disables REST polling when connected and polls ~8s when disconnected; `ConnectionBanner` shows API connection in the nav.
- Persistent user data lives under `{DATA_DIR or home}/PrintQueData/` via `api/utils/paths.py` (JSON state files, `uploads/`, logs, migration backups).
- Backend uses Flask-SocketIO with `async_mode='threading'`; background threads that emit Socket.IO events should use `utils/socketio_emit.py` (`emit_status_update` / `safe_emit` with app context). Never emit while holding `WriteLock(printers_rwlock)` — it deadlocks read paths (`api_get_printers`, monitors). Avoid `increment_queue_sent_count` and queue disk writes inside that write lock; `status_poller` defers them until after the write section. On API restart, status poller preserves persisted printer state until live status is confirmed (`BAMBU_LIVE_STATUS_SEEN` / `PRUSA_LIVE_STATUS_SEEN`); first poll batch waits `STARTUP_POLL_DELAY_SECONDS` (5s). OS-thread workers and native locks: `utils/threading_compat.py`, `spawn_os_thread` in `printer_utils.py`.
- Global `enhanced_prusa_ejection_monitoring` thread (~10s) is named "Prusa ejection monitor"; it skips `type == 'bambu'` (missing `type` defaults to `prusa`). Its log errors are usually `printers_rwlock` read timeouts, not Prusa ejection running on Bambu.
- Library catalog persists in `library.json`; print queue jobs in `queue.json` (`QUEUE_JOBS`; `ORDERS` alias). React uses `/api/v1/library` + `/api/v1/queue`; legacy `/api/v1/orders` in `routes/__init__.py` overlaps queue behavior and is slated for deprecation. `sent`/`quantity` survive API restart; startup does not run distribution. Distributor walks the queue front-to-back (`sent < quantity`); jobs snapshot library metadata and reference ejection presets by `ejection_code_id` (G-code resolved at runtime). Queue copies always upload the same library filepath at sliced XY — no per-copy bed spread/transform yet (planned for mixed `.gcode`/`.3mf`, Bambu+Prusa). UI lists library and queue **newest-first** (`sortLibraryNewestFirst` / `sortQueueNewestFirst` in `paginated-search.ts`); queue drag-reorder still mutates canonical API array order while `#` ranks use the displayed sort. Queue table shows **Total** (editable), **Completed** (`max(0, sent − inProgressPrinters)`), **In progress** (printers actively on job via `getQueueJobActivity` in `printer-queue-job.ts`); backend still only stores `quantity`/`sent` where `sent` increments on copy **start**, not finish. On Bambu, `sent` increments only on PREPARING/PREPARE→PRINTING (not FTP upload, pause/resume, or OFFLINE/ERROR recovery); `count_incremented_for_current_job` is persisted after increment and must not be cleared on transient OFFLINE/idle updates. `periodic_pending_distribution_check` (PendingDistribution thread, every `Config.DISTRIBUTION_INTERVAL` / 30s) retriggers distribution when partial jobs and READY/IDLE printers coexist — fixes event-only dead states (e.g. Ready + 1/N with no error). Queue jobs may store `last_error` / `error_events` via `record_queue_job_error` in `library_queue.py`. Legacy `orders.json` is migrated on load. Queue/ejection mutations must invalidate or patch the React Query `['queue']` cache (not `['library']`). Queue delete is soft-delete by queue job `id` (`DELETE /api/v1/queue/<id>`); `GET /queue` omits `deleted: true`, but Socket.IO `status_update` may push the full `QUEUE_JOBS` list (including deleted rows) and briefly undo optimistic UI deletes until the next poll. Library delete (`DELETE /api/v1/library/<id>`) and file replace (`PUT /api/v1/library/<id>/file`) are blocked (409) when `can_replace_library_file` / `library_item_has_active_prints` finds a partial job (`0 < sent < quantity`) or a printer with matching `order_id` in PRINTING/COOLING/EJECTING; fulfilled jobs (`sent >= quantity`) and FINISHED printer state do not block. Library replace UI uses `parseApiErrorMessage` for API error toasts (status code is not in thrown message).
- Dashboard/stats via `GET /api/v1/system/stats`: `total_filament` is kilograms (do not divide by 1000 in the UI); `queue_pending_count` = jobs waiting (`sent === 0`); legacy `in_queue_count` = partial multi-copy only (`0 < sent < quantity`); `active_prints` = printers in PRINTING; `completed_today` counts fulfilled queue jobs when the last copy is counted (at `sent` increment), not when the print physically finishes.
- Bambu LAN prints: `upload_to_bambu` STORs to the FTP root (bare filename); MQTT `project_file` uses `file:///sdcard/<name>` via `paths_for_stor` (P1 maps root → SD). Never use `cache/` or `sdcard/` FTP prefixes. MQTT `reason: error string` is a generic firmware placeholder; richer detail is decoded in `bambu_errors.py` from `print_error` / HMS on status pushes. Bambu keeps two states: persisted `PRINTERS` (UI, distribution) vs in-memory `BAMBU_PRINTER_STATES` (MQTT). `send_bambu_print_command` can block on stale ERROR while UI shows Ready; `clear_stale_bambu_error_if_idle` / `bambu_error_looks_stale` auto-clear when gcode_state is idle (distribution and poller call this).
- Bambu bed/nozzle temps in the UI come from MQTT cache (`BAMBU_PRINTER_STATES`), updated when payloads include `bed_temper`; firmware often stops sending temps when idle after a job. While `COOLING`, `CoolingMaintain` / `request_bambu_status_for_cooling` issue throttled MQTT `pushall` so threshold checks and UI broadcasts do not freeze on stale readings.
- Ejection G-code preview is client-side (`app/src/lib/gcode-simulator.ts`); G20/G21 recognized in preview. Bambu ejection (auto and manual test via `send_bambu_gcode_command`) sends preset G-code **verbatim** over MQTT `gcode_line` (strip comments/blanks, auto-append `M400` only) — **no coordinate transform**; PrintQue has no per-printer bed size/origin config for ejection (connection fields only). Sends sequentially with per-line ACKs — fire-and-forget bursts drop lines after the first ACK. `bambu_states_lock` must be an `RLock` because MQTT `on_message` re-enters from ACK callbacks. Auto-ejection completes after all script lines ACK (`_complete_bambu_ejection`), not on early preamble `M400`s. Ejection runs only when `count_incremented_for_current_job` is true. Ejection is post-print only and does not change where the next job prints. After a real print, slicer end G-code often parks the head left of center, so the same X park line can look weaker than an idle manual test; firmware may also limit XY with a part still on the bed — split Z-then-X moves help. Saved ejection presets in `PrintQueData`/`ejection_codes.json` are not auto-updated when repo defaults change. Default shipped ejection (`default_settings.py`) targets A1 Mini machine coords (center ≈ X180 Y180, not 0–180 bed grid): park left X60 (X180 = center; X50 off printable area); `M211 X0 Y0 Z0` before out-of-bed moves; Y-4 crossbar nudge; bed cooldown via job setting not M190/G4 in script. `DELETE /ejection-codes/<id>` returns 409 listing library/queue/default-setting blockers; UI `parseApiErrorMessage` surfaces API errors. Queue prints use FTP+`project_file`; ejection does not yet use FTP+`gcode_file`.
- Bambu tracks “job ran” twice: MQTT `job_reached_running` in `bambu_handler` vs persisted `count_incremented_for_current_job` (poller, only on PREPARING/PREPARE→PRINTING). `bambu_handler` can ignore spurious FINISH before RUNNING; `status_poller` may still record `bambu_never_running` on FINISHED when `count_incremented` is false **without** checking `job_reached_running`—missed poll edges leave successful prints (especially 1/1 at 0/1) with a Start error. Cancel/stop should accept stuck jobs (e.g. `order_id` set while state is READY, or MQTT still PREPARING).
- REST `/api/v1/printers/<name>/stop` uses `schedule_stop_print_by_name`; `/pause` and `/resume` are still success-only stubs (real logic in legacy form routes / `print_jobs.py`).
- Local CI expectations after edits: `ruff check api/` and `cd api && pytest` for Python; `cd app && npm run lint`, `cd app && npx tsc --noEmit`, and `cd app && npm run test` for TypeScript (Biome is required for commits even though GitHub CI does not run it yet).
